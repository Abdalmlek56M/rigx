# التنفيذ الهندسي المستقل والمنضبط

هذه المهارة تضبط المخاطر دون تحويل الوكيل إلى منفذ حرفي لقائمة ملفات. الهدف هو إكمال النتيجة المعتمدة، وليس تقليل عدد الأسطر أو التعديلات بأي ثمن.

## قبل التعديل

1. تحقق من جذر Workspace المصرح به، واقرأ `AGENTS.md` و`NEXT_TASK.md` و`PROGRESS.md` والمهارات والوثائق المتصلة بالهدف.
2. حوّل طلب المالك إلى **Task Charter** موجز: النتيجة المطلوبة، السلوك المتوقع، ما يدخل الهدف، الحدود التي لا يجوز تجاوزها، ومعايير القبول.
3. افحص الحالة الفعلية والاستدعاءات والاعتماديات قبل التعديل. أنشئ Baseline متناسبًا: اختبارات ذات صلة، حالة Build، Screenshots عند التغيير المرئي، أو فحوص البيانات عند التغيير الحساس.
4. احتفظ بنسخة رجوع غير متعارضة قبل التغيير الواسع. لا تستبدل نسخًا سابقة أو أرشيفًا قائمًا.
5. افصل قرارات المنتج/الأعمال عن التفاصيل التنفيذية. لا تخترع سياسة مالية أو مخزنية أو قانونية أو صلاحية عند غموض جوهري؛ ارفع القرار المحدد فقط.

## أثناء التنفيذ

1. افهم السبب الجذري وسلسلة الاعتماديات. عالج العيوب المترابطة معًا، ووسّع التغييرات إلى كل الطبقات والاختبارات اللازمة لإكمال الهدف.
2. لديك استقلالية في القرارات التقنية اليومية، واختيار الأنماط والمكونات والأدوات، وإعادة تنظيم الجزء المتأثر إذا كان ذلك يحسن النتيجة بوضوح.
3. نفّذ التحسينات الضرورية المرتبطة مباشرة بالهدف، حتى إن لم تُذكر حرفيًا. لا تبدأ Feature تجارية مستقلة أو Milestone لاحقة لمجرد ظهور فرصة أثناء العمل.
4. اجمع العمل في دفعات منطقية متكاملة. لا تتوقف لطلب موافقة على أسماء المتغيرات أو تقسيم المكونات أو إصلاحات صغيرة واضحة.
5. حافظ على التغييرات السليمة والملفات غير المرتبطة. لا تغيّر Git state أو إعدادات النظام خارج التفويض، ولا تعمل جهتان كاتبتان على Workspace نفسه بالتوازي.
6. طبّق قواعد التحقق الحساسة في Backend/قاعدة البيانات، لا في الواجهة وحدها. لا تغيّر Schema أو بيانات دائمة أو سياسات مالية/مخزنية دون موافقة مستقلة.
7. عند غياب Git، لا تعرض Git Diff؛ قدم قائمة الملفات ومقارنة موثقة قبل/بعد أو Patch قابلًا للمراجعة.

## حدود التوقف وطلب القرار

توقف واطلب موافقة المالك فقط عند: تكلفة/اشتراك/رصيد مدفوع، نشر عام، حذف/تغيير بيانات دائمة، Migration أو تغيير إنتاجي، تغيير تجاري/مالي/قانوني، تغيير صلاحيات أمان جوهري، أو غموض لا يمكن حسمه دون اختراع سياسة.

لا تتوقف بسبب مشكلة تقنية مترابطة يمكن فحصها وإصلاحها بأمان داخل الهدف.

## الإغلاق

1. أعد تشغيل الاختبارات المتأثرة، وأضف اختبارات للحالات التي كشفتها المشكلة، ونفّذ Regression مناسبًا للمخاطر.
2. افحص Diff والملفات التي حُذفت/أُنشئت، والأسرار، والتبعيات، والآثار الجانبية.
3. حدّث الوثائق وسجلات الحالة بما حدث فعلًا فقط.
4. سلّم تقريرًا يوضح الهدف والسبب الجذري والقرارات والملفات والاختبارات والنتائج والقيود وما لم يُنفذ وسببه.
5. لا تبدأ هدفًا جديدًا أو Milestone تجارية تالية تلقائيًا بعد التسليم.
