# سلامة قاعدة البيانات والمخزون

## الإجراء

1. ارجع إلى ERD وقواعد العمل وسير العمل وسجل الأسئلة قبل اقتراح قيد. لا تحوّل خيارًا معلقًا إلى قاعدة.
2. لكل علاقة، حدد الأعمدة المرجعية ومفاتيح `PRIMARY KEY`/`UNIQUE` المطلوبة، وصرّح بـ `NULL` أو `NOT NULL` لكل حقل. افحص أثر `MATCH SIMPLE` على المفاتيح المركبة.
3. افصل الضمانات: `FOREIGN KEY` للعلاقة، `UNIQUE`/الفهرس الجزئي للفرادة، `CHECK` لقيم الصف نفسه، وTrigger أو معاملة للتحقق عبر عدة صفوف. لا تنسب تحقق التطبيق أو الشرح النثري إلى PostgreSQL.
4. في الحركات المخزنية، عرّف مصدر الحقيقة لكل كمية، إشارات الإضافة والصرف، حالات الاستلام والحجر والفقد، ومعادلات عدم التجاوز وعدم الازدواج. ميّز القيود التي تتطلب قفل صفوف أو معالجة سباق.
5. للسيريالات، اربط سيريال الاستلام بتخصيص الصرف نفسه بمفتاح مركب يضم المعرّف والسيريال. عرّف دورة التخصيص النشط والتحرير، واستعمل قيدًا فريدًا ذريًا نهائيًا مع قفل صف السيريال ومعاملة EF Core.
6. وثّق `ON DELETE` لكل FK تاريخي/مخزني؛ احفظ السجلات الدفترية، واستخدم الإلغاء أو القيد العكسي وفق السياسة المعتمدة.
7. اربط كل ضمان باختبار PostgreSQL محدد، واذكر أن الاختبار مخطط ما لم يتم تشغيله بالفعل.

## مراجعة EF Core

تحقق من تطابق Fluent API أو `IEntityTypeConfiguration` مع مخطط PostgreSQL: المفاتيح المركبة، الفهارس الجزئية عبر SQL filter، `DeleteBehavior.Restrict`, precision، check constraints، وإدارة المعاملة/التزامن. لا تدّعِ أن إعداد EF وحده يثبت وجود القيد قبل إنشاء migration وتطبيقها والتحقق منها.
