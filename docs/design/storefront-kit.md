# Storefront design kit — the written rules

Applies to the storefront (`apps/web/src/components/ui`) and, for buttons, tokens and tables, to the admin kit (`features/admin/kit`). The owner's bar: comfortable, beautiful, professional; cards with titles; little noise; one clear action per area; icons instead of words where the icon is clear; formal Arabic; light and dark both work.
`apps/web/src/components/ui/kit-rules.test.ts` enforces the rules a search can prove (hard-coded buttons, `disabled:opacity-*`, `text-error`, ad-hoc heading sizes, hand-made status pills, hand-made radio cards). A new rule that can be proved by a search goes there.

## 1. Tokens (`app/globals.css`)
- Colour only through tokens (`bg-surface`, `text-ink`, `text-ink-muted`, `border-line`, `bg-paper` …). Never a hex value in a component.
- **Red as text or an icon is `text-error-text`**, never `text-error` (dark theme lifts it to a readable salmon). `bg-error` / `border-error` stay for fills and edges.
- `--muted` is the quiet text colour used on grey fills (disabled buttons, placeholders); it is lifted in dark too.
- Spacing steps: 4 / 8 / 12 / 16 / 24 / 32 (`gap-1 … gap-8`). Use the nearest step, never an in-between value. Card padding comes from `Card` (`p-5 md:p-6`); do not set it again.

## 2. Heading scale
| Utility | Size | Use |
|---|---|---|
| `type-display-title` | 22 → 30 px (from `md`) | The heading of a home section (rails, FAQ, services blocks). One per section. |
| `type-page-title` | 28 px | The `h1` of a page (`PageHeader`). Exactly one per page. |
| `type-section-title` | 17 px | A card title, a panel or drawer title, an empty state title, a build/product card name. |
| `type-value` | 14 px bold | A value in a label/value pair. |
| `type-label` | 12 px muted | A label above a value, a caption, a column of small print (add `font-bold` for a group label). |
Exceptions, on purpose: the hero `h1` (display size, home only), the print documents (invoice, quote) and the footer column headings (13 px caps on the graphite strip). Everything else uses a utility above, never `text-[22px]` or `text-lg` on a heading.

## 3. Label above value
A fact is a **label** (`type-label`) over a **value** (`type-value`), side by side only in `InfoGrid` rows (two columns on `md`, one on phones). Never `label: value` in one run of text, never a dot or a dash between the two words of a label ("اسم التجميعة (اختياري)", not "اسم التجميعة · اختياري"). Optional fields say "(اختياري)" in brackets; counts are a pill.

## 4. Buttons
One kit, five variants (`components/ui/Button.tsx`; the admin has its own copy with the same names in `features/admin/kit/Button.tsx`):
| Variant | When |
|---|---|
| `primary` (graphite) | **The one main action of a screen or form** (send, save, confirm). At most one per screen area. |
| `accent` (orange) | A buying action only (add to cart, order). |
| `secondary` (outlined) | Every other action. |
| `ghost` | Quiet actions inside rows and toolbars. |
| `danger` | Delete, cancel, reset. Never the only button; the safe choice sits next to it. |
- **Icon button** (`IconButton`, or `Button iconOnly`): when the icon explains itself (close, copy, share, heart, trash, edit, WhatsApp, back). It always has `label`: that is the `aria-label` and the hover tip. Words stay on the one main action and on any action whose icon is not obvious. Never an icon plus a word that says the same thing (a globe and "اللغة").
- **Text link vs button.** A link that goes somewhere to read (a policy, another page, "see all") is a text link in the content colour with an underline on hover; a link that *does* something the page is for (go to checkout, open the builder) is a `ButtonLink`. An underlined orange sentence that reads like a broken link is never used for help: use a `HelpLink` pill.
- **Pill / chip.** A pill (`rounded-full`) is a *choice or a fact*, never an action: filter chips and tabs (selected = graphite fill), condition and status badges (`StatusBadge`), counts (`CountBadge`), the "reset filters" chip. A rectangle with `rounded-control` is an action.
- Sizes: `md` (44 px high) by default, `sm` (36 px) inside a table row, a card title row or a toolbar; on phones both keep a 44 px touch target.
- **Disabled.** A disabled button is flat grey with a muted label and a hairline edge (`.btn-off`, light and dark), the cursor says "not allowed", and it does not hover or press. It is never a dimmed copy of the live colour: no `disabled:opacity-*` and no `opacity-50` on a button anywhere. While an action runs, `loading` shows a spinner and keeps the colour. A link that cannot be followed yet uses `aria-disabled` (the kit styles it the same way) and drops its `href`.
- A hard-coded button (`rounded-control` plus a fill) outside the kit is a defect.
- **Status marks.** A status, an availability or a condition is shown only by `StatusBadge` (tone: neutral / success / warning / danger / info), `StockDot` or `ConditionBadge`, in the storefront and in the admin alike. A screen maps its own states to a `StatusTone`; it never draws its own pill, tag or coloured word. A part's warranty beside it is `WarrantyTag`: an orange shield and "ضمان 3 شهور" (the word is added to a bare period; a label that already names the warranty is kept).
- **Choosing between a few options** (new / used, delivery / pickup, payment method, who can see a build) is a **tile** (`components/ui/ChoiceTile.tsx`): the icon above the word, an orange glowing frame when chosen. A rectangular button is for an action or a link, never for a choice.

## 5. Cards, tables, states
- **Card** (`Card` with a `title`, optional `icon` and `actions`): every group of content on a page. A title row is the icon (muted, 18) + `type-section-title`; page-level actions go in the page header, card-level actions on the end of the card's title row.
- **Admin table** (`DataTable`): header row on `bg-paper`, bold `text-ink` 13 px with a hairline under it, identical in every list; the first column of people is a `NameCell` (bold name, phone or code under it in mono, never forced to capitals); numbers align to the end; on phones a row becomes a card with the column names above the values.
- **Empty state** (`EmptyState`): an outline icon in a circle, one title, one helping line, one action at most. **Loading**: a `Skeleton` that has the shape of the content; never dim real content to 60 % while it reloads (keep it, mark it `aria-busy`). **Error** (`ErrorBlock`): what failed, in formal Arabic, plus a retry button.
- **Icons** come only from `components/ui/icons` (one stroke). Sizes: 14 inside a badge or a dense row, 16 in a `sm` button, 18 in an `md` button and next to a card title, 20 in a header action, 26 in an empty state. A decorative icon is `aria-hidden`.
- Motion: only `transform` and `opacity`, under 250 ms, and every animation switches off with `prefers-reduced-motion` (the global rule already does it; do not add a `transition` that needs a second opt-out).

## 6. Motion and atmosphere (4.11 C)
All of it is CSS first, decorative, and off or still under `prefers-reduced-motion`. No animation library.
- **Hover effects belong to a mouse.** Anything that depends on hover (card lift and glow, the 3° tile tilt `Tilt`, the card's second photo, the photo magnifier `.zoom-photo`, the service gauge) is inside `(hover: hover) and (pointer: fine)` or is only started by a mouse `pointerenter`. A touch screen never sees it and never downloads what it needs.
- **Nothing extra before the first interaction.** The second card photo is mounted on the first pointer-enter, not in the page; a tab panel rises in only after the visitor switched tabs; a counter starts when it scrolls into view and its server markup already holds the final value.
- **Sliding indicator** (`useTabIndicator` + `.tabs-slide` + `.tab-indicator`): for a row of tabs of unequal width. The live tab is marked `data-active="true"`; before the first measurement it paints its own fill, so there is no flash. A row of equal tabs (condition tabs, the grid/list toggle) uses a plain `translateX` instead. The indicator is the one element allowed to transition its size as well as its position (it is absolutely positioned).
- **State pulses** (`.step-pulse`, `.dot-pulse`) mark the current step of an order only; **the warranty battery** (`.battery`) is green above 50 %, amber to 20 %, red below, empty when expired.
- **Section titles** (`type-display-title` + `title-hook`) carry a short orange line that draws in as the title scrolls into view (scroll-driven, only where supported).
- **Dark glow** (`.page-glow`): two very faint lights (orange and blue, 10–11 % alpha) drift behind the whole storefront; one fixed CSS element, no canvas, off under reduced motion and in print.
- **Dark circuit canvas** (`Atmosphere`): one canvas behind the home hero and the hero-like page headers (`PageHeader atmosphere`: catalog, builder, builds, services). Never on cart, checkout, account, login or policies (the page glow stays everywhere in the storefront). The parent is `isolate`; the canvas chunk is only downloaded in the dark theme; it is still for reduced motion, phone-sized screens and low-end devices (4 cores or fewer), absent with save-data, paused when hidden or off screen, and capped at 30 frames a second.
- **Dark photos**: a product photo sits on `.photo-frame` (soft backdrop, multiplied) so white studio backgrounds do not glare; the light theme is untouched. The product page gallery uses `.photo-stage` instead: the card surface behind a blurred, scaled copy of the same photo (`.photo-stage-fill`, decorative, dimmer in dark) with the real photo whole (`object-contain`) on top. The storefront template gives every page `scroll-margin-top` so the page header never lands under the sticky site header.
- Copy: a section title is a short hook, not a label ("ما القطعة التي تبحث عنها؟"). It makes no claim the store cannot back.

## 7. Builder and shared builds (4.11 D)
- **Choice tile** (`ChoiceTile`, `ChoiceRadioTile` for forms, `ChoiceLinkTile` for a link; `.choice-card`): a pick between a few options, with an icon above the word. The chosen tile glows (orange edge, soft shadow, accent fill); under a mouse it lifts 2 px; a tile that cannot be chosen is flat grey and says why in its note. It is a card (`rounded-card`), not an action, so it never uses a button variant.
- **Wizard** (home "اقترح لي تجميعة"): one question per step, a step indicator that says where the visitor is, choosing lights the card for 280 ms and slides the next step in from the reading side (`.wizard-panel[data-direction]`, 220 ms, flipped in RTL; no slide on the first paint). Every step can be skipped and the last one shows the choices with an edit pencil each.
- **Status dot** (`.status-dot` + `data-tone`): a dot that sends out a ring. Green = compatible, amber = a warning, red = a conflict (a build that cannot be ordered is red, not amber), grey and still = nothing to judge yet.
- **Power meter** (`PowerMeter`): the estimated draw against the output of the power supply, with a tick at the 80 % headroom the API warns at. The sentence under it is the advice: enough / tight, look for N W / not enough, look for N W / choose a supply of N W. N is a multiple of 50 W that keeps the estimate under 80 %. The two power problems are not repeated in the problem list.
- **Case blueprint** (`CaseBlueprint`): one layered SVG (see §12 for the 4.11 P2 redraw), one part per builder slot, named in the singular (`slot-names.ts`). A part is a dim dashed outline until a part is chosen, then it fills with the accent, glows and carries its name; the slot being chosen glows; a slot in a conflict is tinted red, in a warning amber. A click on a part chooses its slot (the slot list stays the keyboard way). Only slots the store has are drawn. Drawings live in `blueprint-shapes.ts`, so a new slot is one entry.
- **Visibility** (`VisibilityPicker`): private / by link / public as three choice cards with the sentence of the chosen one under them. A public build says where the store's decision stands (waiting, shown, not approved) next to it. A visitor who is not signed in sees only a sign-in note.
- **Reactions** (`BuildReactions`): a heart and a like, each with its count, as small secondary buttons (`aria-pressed`). The screen changes at once and the server's answer replaces the counts; a failed save flips back and says so; a visitor who is not signed in is sent to sign in.

## 8. Documents and customer feedback (4.11 E2)
- **Document** (invoice, build quote): a fixed-size light paper (`.doc-paper` forces the light palette, so screen, PDF and picture agree). The invoice is 860 px wide (`INVOICE_WIDTH`), the quote 1080 × 1350; `DocumentFrame` scales the invoice to the screen (`transform`, anchored and centred) and drops the scale in print (`data-document-frame` / `data-document-paper` in the print CSS). Header band in graphite with the logo and the document title, boxed groups (store, customer, details), a lines table with a **condition column** (a build's parts carry theirs): only the words "جديد" / "مستعمل" (`ConditionBadge`), then totals with a graphite grand-total band.
- **Copy as picture** (`CopyImageButton` in `components/document`, rendering in `lib/document-image`): one button next to the print button for every document; the picture is made at the paper's design size, so a phone gets the same image as a desktop. Where the clipboard cannot take a picture it saves a file; Safari and iOS may fail (the PDF stays).
- **Order lines** in the account list open in place (`OrderItemsAccordion`: a full-width button with a chevron, `aria-expanded`); the full order page stays one click away.
- **Notifications** (`NotificationBell`): the panel hangs under the bell from `sm`, and on a phone is as wide as the screen less its gutters (`fixed`, `inset-x-3`) instead of hanging off the bell; each entry has a picture for its kind (order, back in stock, store reply) and an orange dot while unread.
- **Feedback form** (`/feedback`): one form, a square choice tile pair (complaint / suggestion), name and phone filled from the account, optional email, subject and order or item reference. It lands in the admin inbox; the store's written reply shows in "طلباتي الخاصة" and in the bell.
- **View count** (`BuildReactions`): an eye and the count before the heart and like, as a quiet label, not a button. The count comes with the reactions, so a gallery card and the shared page show it the same way.

## 9. Admin productivity (4.11 F1)
- **Compact choice tile** (`ChoiceTile compact`, also on `ChoiceLinkTile` / `ChoiceRadioTile`): the icon beside the word in one 36 px row (on a phone the word alone, so the three catalog tiles share one row), for a filter above a list (the catalog's all / new / used). Its touch area is stretched to 46 px with a pseudo-element, so a phone still has a 44 px target. A tile that chooses between a few options in a form stays the full square.
- **Catalog filter panel**: groups sit 16 px apart; rows are 40 px high in the phone drawer and 32 px in the desktop sidebar (`lg:`); "إزالة الكل" is a chip on the same line as the "تصفية" title.
- **Command palette** (`features/admin/palette`): Ctrl+K / ⌘K anywhere in the admin, a button in the sidebar and a search icon in the phone bar. One native modal dialog with a combobox (`aria-activedescendant`, arrows, Enter, Esc). It lists quick actions, then pages (the sidebar's own entries), then records found by code, name or phone (orders, customers, stock items, purchases). `staticEntries` and `recordSources` take the user's permissions: nothing is shown that the person could not open. The orders list has no server search, so the palette keeps the newest 300 for a minute and filters them with the page's own `filterOrders`.
- **Drawer for a detail** (`ModalSheet wide`): the selected order opens over its list (the list keeps its place and filters) instead of below it. Content order: warnings, the action cards (status, payment, shipping), the facts, the extras. The page address keeps `?id=`, so a link or the palette opens the drawer.
- **Toast with undo** (`useUndoToast`; `system/useUndoDelete` for a delete that goes to the trash): a success toast with a "تراجع" button that stays 8 seconds (5 for a plain one). A person without `System.Trash` gets the plain toast. The toast stack is a manual popover in the browser's top layer, so a toast is seen above an open drawer or dialog.
- **Table density** (`kit/density-rules`, `useDensity`): comfortable (default) or compact, chosen in the user menu or from the palette, kept per signed-in user in this browser. `DataTable` rows and header read `--row-py`, which the shell sets from `data-density`.
- **Stock age** (`inventory-rules`: `STOCK_AGE_DAYS`, `stockAge`): the days column is plain text up to 15 days, an amber `StatusBadge` past 15 and a red one past 30; an item with nothing available is never flagged. The two limits live in that one constant.
- **POS keyboard** (`pos/pos-shortcuts`): F2 or / = item search, F4 = customer search, Ctrl+Enter = confirm, Ctrl+Shift+Enter = save pending, ? = the legend (the keyboard button in the header). Enter in the item search adds the item whose code was typed or scanned (or the only match). While a field has the focus only the F-keys and Ctrl+Enter act. A blacklisted customer is flagged in the search results and the customer card, and the summary repeats it (the API's `PosCustomerView.isBlacklisted` and `PosPreview.customerBlacklisted`, so a cashier who may not read the blacklist is still warned).
- **Purchase lines**: the margin (price minus cost, in pounds and as a share of the price, as on the dashboard) appears beside the cost and the price as they are typed, red when negative; Enter in a used piece's serial field (a scanner's last key) repeats the line below it and moves the focus to its serial; a serial typed on two lines is marked on both.

## 10. Admin ordering, pictures and the activity log (4.11 F2)
- **Drag to order** (`features/admin/kit/DragSort.tsx`, the only file that imports `@dnd-kit/core`; a test fails on any other import, so the library stays in the admin chunks). `DragSort` wraps a list and reports `onMove(active, over)`; `DragItem` is one item that can be dragged and dropped on. A mouse drags after 6 px, a finger after a 250 ms press (so a swipe still scrolls). Two kinds of item: a **tile** that is dragged by itself (photos), and a **row** with a grip handle (`handle`, the six-dot `GripIcon`) for lists that have buttons and a name to click (categories, brands). The item under the one in hand gets a dashed orange outline. The pure part (`kit/reorder-rules`: `moveKey`, `dropOn`, `inOrder`, `sameOrder`) is tested.
- **The arrows stay.** Dragging never replaces the keyboard way: photos keep the earlier / later / main buttons, brands have two arrows on every row, categories on the selected row. A list that is filtered is not orderable (brands), and a person without `Catalog.ManageTaxonomy` / the photo permission sees no grip and no arrows.
- **The new order shows at once**, is saved with one call that names every record once (`PUT /admin/catalog/brands/order`, `…/categories/order` with the parent), and is dropped as soon as the list is read again. The API refuses a list that is not exactly the records as they are now (409) and bumps the version of the records that moved, so a form that was open on an old copy is refused instead of overwriting the order. A category is ordered among its siblings only; to change its parent, edit it. A new category or brand goes last. The old "sort order" number field of the category form is gone.
- **One picture slot** (`kit/ImageSlot`): preview, upload or change, paste, remove after a confirmation; used for the category picture, the brand logo and the two store logos. **Paste** (`kit/use-image-paste`, `kit/PasteImageButton`, `kit/clipboard-image`): the area around any admin picture upload takes the focus on a click and a Ctrl+V of a picture uploads it (only a png, jpeg or webp; text pastes behave as usual); where the browser lets the page read the clipboard a "paste" icon button does the same (a phone has no Ctrl+V). A test fails on an admin file that accepts a picture upload and has neither.
- **Brand ↔ category is a suggestion** (owner decision 22 Nov): the brand form has one pill per category ("الأقسام المقترحة"); in every brand picker of the stock, purchase and build forms the brands suggested for the chosen category (or one above it) come first with a small "مقترحة" mark, and every other brand stays in the list. It never hides or refuses a brand.
- **Activity log by month, then day, then entry** (`features/admin/audit`): the screen opens on a header per month with its count (`GET /admin/audit/months`); the newest month is open and shows one card per day (the date, the weekday, "today" / "yesterday", the count and the first two people behind it, `GET /admin/audit/days?month=`); a day opens in a side sheet (a full screen on a phone) with its entries by kind of work, and an entry opens in the same sheet with its before / after. The URL keeps `day` and `entry`, the filters (section, item, action) narrow the months and the days. A change that points to a brand, a category, a product or a user shows the name (the API reads the names for the one entry it returns); an id that is none of them reads "سجل مرتبط".

## 11. Visual polish round (4.11 P1)
- **Soft sliding indicator** (`useTabIndicator` + `.tabs-slide` + `.tabs-bar`, colours from `--ind-bg` / `--ind-fg`): the default indicator is the solid graphite pill (home tabs); a nav that lists *places* uses the soft one: an orange-tinted fill (`--orange-soft`), ink text, the icon in `orange-text`, and a 3 px orange bar on the reading edge (on a phone's horizontal tab row, along the bottom). The account side nav uses it: `AccountShell` stays mounted while its pages change, so the indicator slides; `account/template.tsx` re-mounts only the page beside it, which rises in (`.page-in`). The nav card is sticky from `md` (`top-24`, on a wrapper, because `.tabs-slide` sets its own `position`). On a phone the nav is a full-bleed horizontal strip of 44 px tabs.
- **Header controls**: every round control of the header (menu, theme, language, bell, account, cart) is `HEADER_ICON_BUTTON` with a 20 px icon, including the menu button on phones; the language button is 14 px bold; the search field has the same hairline edge as the icon pill (`border-line`, `input-line` on hover).
- **Brand logo** (`features/catalog/BrandMark`): shown only where the brand is the subject — the eyebrow of the product page (logo, then the name) and the catalog's brand filter (name next to the tick, logo at the end of the row). Never on a product card. The logo sits on a small framed chip (`.photo-frame`, so a white logo background melts into the dark backdrop). The name is always written beside it, so the picture is decorative (empty `alt`); a brand with no logo, or a logo that fails to load, draws nothing (no frame, no gap).
- **Admin sidebar**: the current page is a lifted row (`footer-line` fill, bold, an orange bar on the reading edge, the icon in orange), not a solid orange block. The groups with more than one area fold from their heading (chevron, `aria-expanded`); a folded group shows an orange dot when something new waits inside it, and the arrow always works: a folded group that holds the current page keeps only that page's row (`nav-collapse.ts`: `visibleAreas`). The folds are kept per signed-in user in this browser.
- **Admin pieces** (`features/admin/kit`): `PageHeader` uses the store's 28 px `type-page-title`; `SectionCard` is the store's card (`cardClass`: same surface and padding) with `type-section-title`; `DataTable` shows the sort direction with arrow icons (a faint hint on the other columns) and an icon with the empty message; `SearchBox` has a search icon on its reading edge. Loading, failure and emptiness are `LoadingCard`, `ErrorPanel` and `EmptyPanel` (`kit/LoadState.tsx`), never a hand-made pulse block, alert box or grey note; `kit-rules.test.ts` fails on the old copies.
- **Values in code-built text** are separated by a comma, never a dot: `joinValues` / `listSeparator` in `lib/format` ("،" in Arabic, "," in English); a date and its time read "13/11، 2:22 م". Digits in messages are Western (0–9) everywhere.

## 12. The case drawing, fans and several drives (4.11 P2)
- **A layered SVG, no library, no 3D** (`features/builder/blueprint-geometry.ts` = the vocabulary and the one `fan()` function, `blueprint-shapes.ts` = the drawings, `app/blueprint.css` = the look). Back to front: the shadow and feet, the steel shell with a glass side panel and two reflections, the fan frames, the power-supply basement with its vents, the board (power-stage heatsink, I/O shield, expansion slots, chipset, M.2 socket, screws), then every slot's part: memory sticks, the card with three fans, the processor, the cooler's fan ring, the power supply with its fan and cables, drives on the front plates, case fans. A drawing is a list of **pieces**: a slot that takes several pieces has one piece per place, listed in the order they fill.
- **Marks have a role and a state.** `data-role` (shell, glass, glare, shroud, mount, vent, ring, blade, hub, chip, cable, screw, shadow, trace) and `data-state` (empty / filled). The scenery (glass, glare, shadow, mounts, shroud) never changes. A part that is not chosen is a **dim outline on a faint fill** (13 % of the ink colour, dashed edge at 55 %): clearly there, clearly not chosen; a chosen one fills with the orange gradient, glows (soft drop shadow), and carries its name (10.5 px, halo). Everything is a token colour, so light and dark both work. The only motion is a slow turn (6 s) of a lit fan, only under `prefers-reduced-motion: no-preference`.
- **Counts light places one by one**: three drives light the three plates, two sticks light the second and fourth slot of the board, four fans light the front middle, the back, the front top and the front bottom (then the top two). The slot's name carries the count when it is a quantity ("رامات ×2", "مروحة ×4"). A processor held twice is still one place (`litPieces`).
- **Slot limits** (`slot-limits.ts`, the same numbers as `BuilderSlot.LimitOf` in the PcBuilder module): storage up to **3 pieces** (separate models; the same model twice is two pieces), fans one model up to **6**, every other slot one model up to **4** (memory sticks). The slot list shows a quantity stepper for memory and fans (`QuantityStepper`, capped by the slot's room and the stock), and a row with its own remove button for every drive. Choosing a drive that is already chosen takes it out; a full slot locks the other choices with the note "اكتمل العدد"; after a pick, storage keeps the focus (a second drive is one more tap) and every other slot moves on to the next empty one. Replacing the model of memory or fans keeps their quantity.
- **The drawing's key** is two swatches under it ("مختارة" / "غير مختارة"); the count of chosen slots is a pill in the card's title row, never "0 / 8" alone under the picture.
- A new slot is still one entry in `SLOT_DRAWINGS` (plus its place in `BLUEPRINT_ORDER`, its name in `slot-names.ts` and its limit in `slot-limits.ts` and in the API).

## 13. Admin batch 1: daily operations (4.11 A1)
- **Side sheet for a record's form** (`features/admin/kit/EditSheet`, over `ModalSheet`): a coupon, an offer, the quick edit of a stock item and an account's statement open in a side sheet over their list (the list keeps its place and filters; the URL keeps `?id=` where it had it), with a title and a close button. A new list screen that edits a record in a form uses it instead of a card under the table.
- **Row shortcuts** (`inventory/InventoryShortcuts`): a column of small icon buttons after the name, each with a tooltip and `aria-label`, 44 px on a phone (`max-md:size-11`), each gated by its permission. The column spans the whole card on a phone (`phoneFull`). The till opens with `?add=CODE` (adds that item) or `?q=` (only searches).
- **Dashboard to-do rows** link to the list filtered the way the count is made (`?todo=` on the orders list, `matchesOrderTodo` mirrors the API's `TodoAsync`); the list shows the filter as a chip with "إزالة التصفية". A count with no screen behind it (returns) links to the nearest list and is listed as missing in the checkpoint.
- **Dates**: every date field is `DateField` (`kit/DateField`: the page's language on the field, left-to-right text aligned to the start). The browser still draws the parts in its own order; a page cannot change that without a custom field. A kit-rules test fails on a bare `type="date"` in the admin.
- **Picture chosen with a form** (`kit/ImageDropPicker`): a button, a dashed drop area, Ctrl+V and the paste button; never the browser's own file input. Pictures that save at once keep `ImageSlot` / the photo gallery.
- **Donut** (`kit/DonutChart` + `kit/donut-rules`): SVG only; seven slice colours that are page tokens (the last is the quiet "other"); the total in the middle and a legend (dot, name, share, amount) under it, so the colour never carries a fact alone.
- **Filter dropdowns that would read as unnamed boxes** (the activity log's four) take `FilterSelect titled`: a small title above. Other bars keep the label as `aria-label`.
- **Technical fields** the database keeps for itself (stamps, row versions, derived keys, token hashes) are not listed in the activity log's "what changed" (`TECHNICAL_FIELDS` in `audit-rules`).

- **Compact sortable rows** (`features/admin/settings/ListEditor`): contact links, lead sources, warranty options, shipping groups and the homepage sections are one line per item: a grip, the fields, an optional chevron that opens the rarely changed fields (`renderDetails`) and a bin; from `md` a header row above names the columns (`columns`, and `labelClassName="md:sr-only"` on the fields).
