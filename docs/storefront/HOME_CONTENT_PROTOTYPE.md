# محتوى الصفحة الرئيسية — Prototype محلي

## الحالة

هذه شاشة إدارة تجريبية (Prototype) داخل `Admin → المتجر → محتوى الصفحة الرئيسية`.
الهدف منها إثبات تجربة الترتيب والإظهار/الإخفاء وتحرير الشرائط قبل بناء إدارة محتوى
دائمة في Backend/قاعدة البيانات.

**ليست CMS ولا ميزة إنتاجية.** لا توجد API ولا جداول ولا Migration، ولا تُرسل أي
تغييرات إلى الخادم.

## كيف تعمل الآن

- الملفات:
  - `apps/web/src/lib/home-layout.ts` — الأنواع والقيم الافتراضية والتحقق من البيانات.
  - `apps/web/src/components/home-layout-provider.tsx` — Context يقرأ ويكتب `localStorage`.
  - `apps/web/src/components/home-content-admin.tsx` — شاشة الإدارة.
  - `apps/web/src/app/admin/home-content/page.tsx` — المسار.
- مفتاح التخزين: `rigx-home-layout-v1`.
- يُحفظ الترتيب والظهور وعنوان/وصف الشريط ونوع محتواه وحد العناصر وترتيب العناصر
  وإخفاء عناصر فردية في **متصفح المستخدم فقط**.
- التغييرات تظهر مباشرة في الصفحة الرئيسية داخل نفس المتصفح، ولا تظهر لمستخدم آخر
  أو على جهاز آخر.
- مسح بيانات المتصفح أو استخدام وضع التصفح الخاص يعيد القيم الافتراضية.
- عند فشل `localStorage` (سياسة خصوصية أو امتلاء) تبقى القيم في الذاكرة للجلسة الحالية
  دون كسر واجهة المتجر.
- الشاشة تعرض تنبيهًا واضحًا بأن الحفظ محلي وتجريبي.

## ما الذي يمكن تعديله

- ترتيب أقسام الصفحة الرئيسية: الواجهة، العلامات التجارية، الأقسام، استكشاف المنتجات،
  دليل الاختيار، أحدث المنتجات، ختام الصفحة.
- إظهار أو إخفاء أي قسم.
- عنوان ووصف مختصر لشريط العلامات التجارية وشريط الأقسام.
- نوع محتوى الشريط: علامات تجارية / أقسام / منتجات.
- حد عدد العناصر (1–24).
- ترتيب عناصر الشريط وإخفاء عنصر بعينه.
- استعادة الافتراضي.

الأزرار تعمل بلوحة المفاتيح، ولها `aria-label` واضح، ولا تعتمد على السحب فقط.

## القيود المعروفة

- لا توجد معاينة منفصلة؛ الصفحة الرئيسية نفسها هي المعاينة.
- لا توجد نسخ متعددة، ولا جدولة نشر، ولا صلاحيات دقيقة لهذه الشاشة.
- لا توجد مزامنة بين المتصفحات أو المستخدمين.
- لا يمكن إدارة نصوص الواجهة (Hero) أو الصور أو الروابط من هذه الشاشة.
- لا توجد نسخة تاريخية أو استرجاع بعد الحفظ.

## متطلبات الإدارة الدائمة (مستقبلية)

قبل تحويلها إلى ميزة إنتاجية يجب اعتماد وتنفيذ الآتي:

### 1) نموذج البيانات

- `HomePage` أو `HomeLayout` كسجل واحد منشور + مسودات.
- `HomeSection` يحمل: `Key`, `DisplayOrder`, `IsVisible`, `SettingsJson` (اختياري).
- `HomeRail` يحمل: `SectionKey`, `Title`, `Lead`, `ContentType`, `ItemLimit`.
- `HomeRailItem` يحمل: `RailId`, `EntityType` (Brand/Category/Product), `EntityId`,
  `DisplayOrder`, `IsVisible`.
- قيود قاعدة بيانات: مفاتيح فريدة، Foreign Keys اختيارية حسب نوع الكيان، فهارس على
  `DisplayOrder`، و`RowVersion` لمنع التعارض.

### 2) الـ API والصلاحيات

- `GET /api/v1/admin/storefront/home` لقراءة المسودة.
- `PUT /api/v1/admin/storefront/home` لحفظ Layout كامل في معاملة واحدة.
- `POST /api/v1/admin/storefront/home/publish` لنشر نسخة بعد التحقق.
- `GET /api/v1/storefront/home` للقراءة العامة المنشورة فقط.
- صلاحية مستقلة مثل `Storefront.Content.Manage`، وفحصها في الخادم لا في الواجهة.
- التحقق من أن الكيانات المختارة موجودة ونشطة، ومن حدود العناصر، ومن عدم تكرار
  المفاتيح، ومن أن كل شريط يحتوي نوع محتوى صالحًا.

### 3) النشر والتحقق

- فصل المسودة عن المنشور، مع نشر صريح ووقت نشر ومن قام به.
- منع نشر شريط فارغ أو نوع محتوى غير مدعوم.
- إخفاء العناصر غير النشطة تلقائيًا في القراءة العامة.
- عدم كسر الصفحة إذا حُذف منتج/قسم/علامة تجارية مرجعية.

### 4) الواجهة

- نفس شاشة الإدارة الحالية مع حالة حفظ/فشل واضحة، وزر نشر منفصل.
- معاينة داخل الشاشة أو في تاب جديد تعكس المسودة.
- دعم RTL/LTR وLight/Dark وReduced Motion ولوحة المفاتيح.
- تعطيل الحفظ أثناء الطلب ومنع النقر المزدوج.

### 5) التشغيل والمراجعة

- Migration مع خطة رجوع.
- اختبارات API للصلاحيات والتحقق والنشر.
- اختبارات واجهة للترتيب والإظهار/الإخفاء وحالات الفشل.
- سجل تدقيق (Audit) لكل نشر.
- توثيق عقد الـ API وحدود الأداء.

## معيار الإغلاق

لا تُعتبر الميزة مكتملة إلا عندما:
1. تُحفظ البيانات في الخادم،
2. تظهر لجميع الزوار بعد النشر،
3. تحترم الصلاحيات والتحقق،
4. تعمل مع الكيانات المحذوفة/غير النشطة بأمان،
5. تغطيها اختبارات API وواجهة،
6. توجد خطة Migration ورجوع موثقة.
