## 2. Half 1 — users & roles, audit restore

### `/admin/users` (two views by `view` in the URL: `users` default, `roles`; switch with `FilterSelect` like `features/admin/audit/AuditScreen.tsx`)
| Piece | Endpoint (under `/api/v1/admin/identity`) | Step-up |
|---|---|---|
| Staff list: search, active filter (`isActive`), paging; columns name, email, roles (role names from the roles list), active | `GET /users?search&isActive&page&pageSize` → `PagedResultOfAdminIdentityUser` | – |
| Invite: full name, email, phone (optional), username (prefilled with the part of the email before `@`, editable), roles (checkboxes) → toast says the invitation email was queued when `emailDispatchQueued` | `POST /users` body `CreateAdminIdentityUserRequest` → `AdminIdentityUserInvitationResult` | – |
| Detail (`?user=<id>`, below the list): edit name/phone, active switch | `GET /users/{id}`, `PATCH /users/{id}` body `UpdateAdminIdentityUserRequest` | – |
| Roles of the user (checkboxes, save) | `PUT /users/{id}/roles` body `AssignAdminIdentityRolesRequest` | **yes** |
| Restrictions: list (type, reason, from, until, active); add Suspension (until date required) or Ban (reason required); reinstate (reason) | `GET /users/{id}/restrictions`; `POST /users/{id}/restrictions` body `RestrictionRequest` (`type` = `Suspension`/`Ban`, `expiresAtUtc` = Cairo end of the picked day, reuse `cairoDayEndUtc` from `features/admin/offers/offer-rules.ts`); `POST /restrictions/{id}/reinstate` (check its body type in the schema) | add: **yes** |
| Google: unlink when linked | `DELETE /users/{id}/google` (only if the user view says Google is linked; if it does not say, leave the button out and report it) | check the schema/endpoint |
| Roles view: list (name, code, user count, permission count); create role (code, name, permissions); edit a role's permissions | `GET /roles`, `GET /permissions` (string codes), `POST /roles` body `CreateAdminIdentityRoleRequest`, `PUT /roles/{id}/permissions` body `UpdateAdminIdentityRolePermissionsRequest` | create + edit: **yes** |

Rules for this half:
- Every step-up action goes through `useSubmit` (it opens the code dialog and retries). Never build another step-up flow.
- Destructive or account-locking actions (deactivate, Ban, Suspension, reinstate, Google unlink, removing all roles) open `ConfirmDialog` first, with one sentence saying what happens.
- **Yourself:** hide deactivate, restrictions and role changes on your own account (the signed-in user id from the existing `/identity/me` hook; find it, do not add a new call). The server is still the authority; this only prevents locking yourself out by mistake.
- Permission picker: group the codes by the prefix before the first `.` (`Sales`, `Inventory`, `Finance`, `System` …); group titles translated with one pure mapper (unknown prefix → the prefix as-is); the code itself shown `dir="ltr"` mono. "Select all in group" per group. Show a warning line (not a block) when a role would get `System.ManageUsers` or any `System.*` code.
- No delete or rename for roles (no API) — leave out, report.

### Audit restore (in `features/admin/audit/AuditEntryDetail.tsx`)
- Button "رجّع القيم دي" when the user has `Audit.Restore` and the entry has changes; `ConfirmDialog` → `useSubmit` → `POST /api/v1/admin/audit/entries/{id}/restore` (**step-up**). After success, reload the entry and the list. Server errors (e.g. the row changed since) show as the form message.

## 3. Half 2 — `/admin/system`
Sections stacked on one page, each shown only with its permission:

| Section | Endpoint (under `/api/v1/admin/system`) | Permission | Step-up |
|---|---|---|---|
| **Trash**: list (kind filter, label, deleted at, deleted by, purge after); restore; delete forever | `GET /trash?kind` → `TrashEntry[]`; `POST /trash/{kind}/{id}/restore`; `DELETE /trash/{kind}/{id}` | `System.Trash`; delete forever `System.Purge` | delete forever: **yes** |
| **Backups**: list (started, trigger, status, size, verified), run now, verify, download | `GET /backups`, `POST /backups`, `POST /backups/{id}/verify`, `GET /backups/{id}/download` | `System.ManageBackups`; download `System.BackupDownload` | download: **yes** |
| **Export**: dataset select (only those the user may export), format, from/to (Cairo days), download | `GET /export/{dataset}?format&from&to` — datasets and permissions: orders `Sales.ViewOrders`, stock-items `Inventory.View`, expenses `Finance.ViewReports`, purchases `Purchasing.View`, money-movements `Finance.ViewVaults`, audit `System.ViewAuditLogs`, customers `Customers.View` (formats: read `src/Host/HardwareStore.Api/Export/ExportRunner.cs`) | per dataset | customers: **yes** |
| **Data reset** (danger zone, last on the page): sections `business`, `content`, `customers` (customers needs business — tick business automatically and explain); the user must type `RESET`; result shows rows deleted and the backup taken first | `POST /reset` body `ResetRequest` → `DataResetResult` | `System.ResetData` | **yes** |

- The page is reachable with `System.Trash` or `System.ManageBackups` (nav). Show the export and reset sections only with their own permissions.
- **Downloads:** add one shared helper `apps/web/src/lib/api/download.ts`: call the typed client with `parseAs: "blob"` (openapi-fetch) and the step-up headers, `unwrap` it (errors stay `ApiError`, so `useSubmit` still detects step-up), then save the blob with a filename you build (`rigx-<dataset>-<from>-<to>.<ext>`, backups: the run's `fileName`). Both backups and export use it; no other download code.
- Purge, reset and backup download use `ConfirmDialog` first. Reset is a two-step: the form (sections + typed `RESET`) then the step-up code.
