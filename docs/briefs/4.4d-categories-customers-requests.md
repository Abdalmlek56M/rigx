## 3. Rules (must)
- **Use the kit.** Lists = `DataTable` + `FilterBar` + `Pager` with `useUrlFilters` (filters, sort and page live in the URL). Saves = `useSubmit` (field errors from ProblemDetails, toast on success, step-up handled for you). Destructive actions = `ConfirmDialog`. No new table, pager, toast, dialog or form-error code. If the kit is missing something you need, **stop and write it in your report** instead of building a second version.
- Data loading = `useLoad` with a `useCallback` loader (see `features/admin/dashboard/Dashboard.tsx`). API calls in one `<area>-api.ts` per feature, typed with `Schemas["…"]`, through `browserApi()` + `unwrap` + `required` (see `features/account/account-api.ts`).
- Every write sends the `rowVersion` it read; on 409 show the server message (`useSubmit` does) and reload.
- Hide buttons the user cannot use (`usePermissions().has("…")`). The API still enforces it; this is only so staff do not see dead buttons.
- **Not in this part:** customer merge (step-up), account suspension/restrictions (`/identity/users/{id}/restrictions`), Google *linking*, "new sale for this customer" (POS is part b), warranty extension (part b), the "History/audit" tab (part f). Leave those buttons out of the screen.
- Text: all strings in `apps/web/messages/ar.json` **and** `en.json` under `admin.categories`, `admin.customers`, `admin.requests`. Egyptian Arabic, short, same tone as `admin.dashboard`. No hard-coded strings in components. Condition labels only "جديد"/"مستعمل" (reuse `common.condition` / `ConditionBadge`). Request type and status labels: one pure mapper (like `features/account/account-labels.ts`), unknown values fall back to a generic label.
- RTL first, works in English (LTR) and in dark mode (tokens only, no raw hex colors). Works at phone width (tables scroll sideways inside their box; forms stack).
- Do **not** change: anything outside `apps/web` (no backend, no migrations, no API contract), `features/admin/kit/*`, `AdminShell`, `admin-nav.ts`, auth or permissions. No new npm packages. No TODOs, no dead code, files under ~300 lines (split components).
- Pages: `export default` a server component that only sets metadata (title from your messages) and renders your client component, like `app/[locale]/admin/page.tsx`. Validate the locale with `hasLocale` as that file does.
