## 2. Goal
`/admin/settings`: one page, a section list (side list on desktop, a `FilterSelect` on phone; the chosen section in the URL as `section`), one form per section. Each section saves on its own.

- Load: `GET /api/v1/admin/storefront/settings` → `StoreSettingsAdminView` (all sections + one `rowVersion`).
- Save a section: `PUT /api/v1/admin/storefront/settings/<section>` with body `{ value: <that section>, rowVersion }` → the whole view back; keep the new `rowVersion` (the next save of any section needs it). 409 → show the server message and reload.
- Sections (path → schema): `store-info` StoreInfoSettings, `contact-links` ContactLinkSettings (list editor), `shipping` ShippingSettings (courier, pickup, default fee/time, governorate groups with fees), `payment` PaymentSettings, `controls` StoreControlSettings (maintenance mode, announcement, sold-out, countdown, guest checkout, minimum order, homepage sections), `whatsapp-templates`, `reviews`, `language`, `invoice`, `lead-sources` (list editor), `warranty-options` (list editor), `sales` (reservation hours, auto release, POS max discount %, sold feed), `watermark` (+ `POST /watermark/reapply` with `ConfirmDialog`, it reprocesses every photo), `backup` (enabled, hour Cairo, retention days).
- Logos: `PUT /logos/{kind}` and `DELETE /logos/{kind}` (read the endpoint in `src/Host/HardwareStore.Api/StorefrontEndpoints.cs` for the kinds and the upload format; reuse the category image upload pattern).

## 3. Rules
- Kit only (`useSubmit`, `ConfirmDialog`, `FilterSelect`, `PageHeader`, `FormMessage`, `Toast`). List editors (links, lead sources, warranty options, shipping groups, homepage sections): one small shared list-editor component inside `features/admin/settings/` (add, remove, move up/down), used by all of them — not one per section. If the kit is missing something, stop and report.
- `useLoad` with a `useCallback` loader; `settings-api.ts` through `browserApi()` + `unwrap` + `required`.
- One pure, tested mapper per section from the view to the form and back (numbers, empty strings → null where the schema allows null).
- Risky switches (maintenance mode on, English off, backups off, guest checkout off) ask with `ConfirmDialog` and one sentence of what customers will see.
- Money and percent fields: plain numbers in EGP / %; show the server's validation message on the field.
- Text in `apps/web/messages/ar.json` **and** `en.json` under `admin.settings`. Egyptian Arabic, short. WhatsApp templates: show the placeholders the server supports (read `StoreSettingsService.cs`) as a hint line, no new placeholder logic.
- RTL first, English, dark mode (tokens only), 375px with no sideways page scroll. Files under ~300 lines (one file per section form). No new npm packages. No TODOs, no dead code.
- Do **not** change anything outside `apps/web`, nor the kit, `admin-nav.ts`, `AdminShell`, auth or permissions.
