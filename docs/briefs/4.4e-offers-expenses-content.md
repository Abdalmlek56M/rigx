## 3. Rules (must)
- **Use the kit.** Lists = `DataTable` + `FilterBar` (+ `Pager` where the API pages) with `useUrlFilters` (filters, tabs, sort and page live in the URL). Saves = `useSubmit` (field errors from ProblemDetails, toast on success, step-up handled for you). Destructive actions (delete, cancel offer, unpublish) = `ConfirmDialog`. No new table, pager, toast, dialog or form-error code. If the kit is missing something you need, **stop and write it in your report** instead of building a second version.
- Data loading = `useLoad` with a `useCallback` loader. API calls in one `<area>-api.ts` per feature, typed with `Schemas["…"]`, through `browserApi()` + `unwrap` + `required`.
- Every write sends the `rowVersion` it read; on 409 show the server message (`useSubmit` does) and reload.
- Money: `formatEgp`; dates: `lib/format.ts` (Cairo time); date inputs send `YYYY-MM-DD`; offer start/end send UTC ISO strings built from the Cairo date the user picked (write this as a tested pure helper).
- Hide buttons the user cannot use (`usePermissions().has("…")`).
- Text: all strings in `apps/web/messages/ar.json` **and** `en.json` under `admin.offers`, `admin.expenses`, `admin.faq`, `admin.articles`. Egyptian Arabic, short, same tone as `admin.dashboard`. No hard-coded strings in components. Status/scope/type labels: one pure mapper per feature, unknown values fall back to a generic label.
- RTL first, works in English (LTR) and in dark mode (tokens only, no raw hex colors). Works at phone width.
- Do **not** change: anything outside `apps/web` (no backend, no migrations, no API contract), `features/admin/kit/*`, `AdminShell`, `admin-nav.ts`, the part d screens, auth or permissions. No new npm packages. No TODOs, no dead code, files under ~300 lines (split components).
- Pages: `export default` a server component that only sets metadata and renders your client component, like `app/[locale]/admin/page.tsx`.
