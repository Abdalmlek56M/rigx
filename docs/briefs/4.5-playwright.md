## 2. Goal
Playwright in `apps/web/e2e/` covering the critical flows, running against a local stack: PostgreSQL (Docker) + the API in Development with Preview enabled + `next dev`.

| Spec | Flow |
|---|---|
| `storefront-order.spec.ts` | open a product from `/ar/products` → add to cart → checkout (pickup, a fresh fake customer `e2e-<timestamp>@example.com`, phone `010…`) → success page → open the tracking link → status shown |
| `login.spec.ts` | `/ar/login` → type the owner email → read the code from the dev endpoint → signed in → `/ar/admin` dashboard visible; also a wrong code shows an error |
| `admin-order.spec.ts` | (signed in as owner) open the order placed by the first spec or create one through the public API → confirm → preparing → (pickup) delivered → record the cash payment → complete |
| `pos-sale.spec.ts` | `/ar/admin/pos` → search an item → add → customer name + phone → cash payment "fill the rest" → confirm → success panel |
| `purchase-intake.spec.ts` | `/ar/admin/purchases/new` → new seller → one part line (model, condition, cost, price) → cash → receive → the new RX code is shown → it appears in `/ar/admin/inventory` |
| `warranty.spec.ts` | `/ar/warranty?q=<invoice or RX code from a completed demo order>` → the warranty result shows |

Shared helpers in `apps/web/e2e/support/`: `signIn(page, email)` (types the email, reads the code with the bootstrap key, types it), `api` (`request` context for the dev endpoints), test data names with a timestamp so reruns do not collide. Store the signed-in state once per run (`storageState`) to save time.

## 3. Rules
- Add `@playwright/test` as an **apps/web devDependency** (exact version, no `^`), Chromium only. Scripts in `apps/web/package.json`: `"e2e": "playwright test"`. `playwright.config.ts` in `apps/web`: `baseURL` from `E2E_BASE_URL` (default `http://localhost:3000`), one worker (the flows share one database), retries 0 locally, trace on first retry, HTML report to `apps/web/playwright-report/` (git-ignored, along with `test-results/`).
- The bootstrap key comes from `E2E_PREVIEW_KEY` (env), never hard-coded secrets. Add the variables to `.env.example` with placeholder values only.
- Global setup: call `POST /api/v1/development/preview/initialize` once (idempotent) so the demo data exists.
- Locators: `getByRole` / `getByLabel` / `getByText` with the Arabic copy from `messages/ar.json`. No `waitForTimeout`; wait for visible elements or responses.
- Each spec independent where possible; never depend on a fixed demo row id — find by text or create what you need.
- Do **not** change app code, backend, migrations, the API contract, CI files. No TODOs, no skipped tests left in.
- Do not add the e2e run to `npm test` (unit tests stay fast).
