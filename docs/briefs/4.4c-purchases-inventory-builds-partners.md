## 2. Screens

### c1 — Inventory `/admin/inventory` (ADM-Inventory)
- `GET /retail/stock-items?search&categoryId&condition&hidden&inStock&page&pageSize` → `PagedResultOfStockItemAdminView`. Filters in the URL (`useUrlFilters`): search, category (tree select), condition (New/Used), availability (`inStock` true/false/all), visibility (`hidden` true/false/all).
- Columns: code, model, category path, condition, available count, cost (sum of `units[].acquisitionCost` of available units; show only when the values are not null — the server nulls them without `Inventory.ViewCosts`), price (in build `prices.inBuild`), expected profit (price − cost, only when cost shows), partner (first unit's partner name from `fetchPartners`, only with `Finance.ViewReports`), status (available / in build `BLD` via units / sold out), visibility, days in stock.
- Row select + bulk hide/show: `POST /retail/stock-items/visibility` (`Inventory.StockAdjust`).
- Detail below the list (pick a row, `?item=<id>` in the URL, `useReveal` on phone): edit form `PUT /retail/stock-items/{id}` (`StockItemUpdateRequest`: model, category, price, with-board/alone extras, warranty label, has box, hidden, internal note; send `rowVersion`, keep `specs` as read), photos upload/delete (`POST/DELETE /retail/stock-items/{id}/photos`, min 3 to publish is the server's rule — show its message), units table (status label, serial, cost, partner + %, received date). Per unit "change partner": `PUT /retail/units/{unitId}/partner` (`UnitPartnerRequest` with the unit's `rowVersion`; partner select = active FinancedParts partners; percent optional = partner default) — only with `Finance.ManagePartnerAgreements`.
- Header actions: "شراء واستلام" → `/admin/purchases/new` (if `Purchasing.CreateOrder`), "تجميعة جديدة" → `/admin/builds` create (if `Catalog.ManageProducts`).
- Leave out (no API): KPI cards, status filter in-build/reserved/sold, partner filter, bulk price change, stickers, Excel export (part f).

### c1 — Purchases `/admin/purchases`, `/admin/purchases/new`, `/admin/purchases/[id]` (ADM-Purchase)
- List: `GET /purchasing/purchases?status&q&page&pageSize` → status tabs/select Draft / Received / Cancelled / all, search, paging; columns code, seller (name + phone), kind, date, lines, total, remaining, status. "شراء جديد" button (`Purchasing.CreateOrder`).
- Form (new and draft edit; a Received or Cancelled purchase opens read-only):
  - Seller: phone lookup `GET /purchasing/sellers?phone=` (and `q`), pick a match or create one `POST /purchasing/sellers` (`SellerRequest`: kind Person/Trader/Company, name, phone, national ID (optional, "بيتحفظ داخلي بس"), governorate, area, source, notes). Edit an existing seller with `PUT` (`Purchasing.ManageSuppliers`).
  - Kind Parts / FullPc ("اشتريت جهاز كامل"); FullPc shows "keep as a build" + build name.
  - Lines (`PurchaseLineRequest`): category (tree), model (free text + suggestions from `GET /retail/models/suggest?q&categoryId`, debounced; picking one fills model and `productId`, never forced), condition New/Used, quantity (Used is always 1), serial, unit cost, sale price (in build) + with-board/alone extras, partner (active FinancedParts partners; only when `Finance.ViewReports` loads them) + percent, hidden, warranty label, has box, internal note. Add / remove lines.
  - Payment: method Cash / InstaPay / Wallet / TradeIn / CashAndTradeIn, paid amount, trade-in value + note (only for trade-in methods), purchase date, notes. Show total and remaining (pure rule: total = Σ qty × unitCost; remaining = total − paid − tradeIn, never below 0 in display; the server stays the authority).
  - Actions: save draft (`POST` → go to `/admin/purchases/[id]`, `PUT` with `rowVersion`), receive (`POST /purchases/{id}/receive`, `Purchasing.ReceiveGoods`, confirm first) → show the created RX codes from `items.items[]` with links to `/admin/inventory?item=<id>`, and the build link when `assemblyId` is set; cancel draft (`POST /cancel`, confirm).
  - A purchase converted from a request shows its notes as saved; no special handling.
- Leave out (no API): purchase photos and the receipt/declaration image on this screen (photos are added per RX item in inventory after receiving), sticker printing.

### c2 — Builds `/admin/builds`, `/admin/builds/[id]` (ADM-Build)
- List: `GET /retail/assemblies` → `AssemblyView[]`, status filter (Draft/Published/Sold/Disassembled) + search on the page; columns code, name, usage, status, parts count, copies, sale price, parts total. "تجميعة جديدة": `POST /retail/assemblies` `{ name, unitIds: [] }` → editor.
- Editor (`Catalog.ManageProducts`), every write sends the build's `rowVersion` and replaces the view with the response:
  - Card `PUT /retail/assemblies/{id}` (`AssemblyEditRequest`): name, Arabic/English public titles (own `dir`), sale price, usage (Gaming/Editing/StudyWork/Streaming — storefront usage labels), sell mode (Full / FullOrSplit), build warranty (label from warranty options; empty = "حسب كل قطعة"), copies, "suitable for" AR/EN.
  - Parts table: name + RX code, condition, cost (when not null), part price, warranty (override flag), partner + %, allocation % / amount. Per part edit `PUT /parts/{unitId}` (`AssemblyPartBody`: part price, warranty label, partner, percent).
  - Add from stock `POST /parts` `{ unitId }`: picker over `GET /retail/stock-items?search&inStock=true` then the item's `units` with status Available.
  - Add a new part (not in stock) `POST /parts/new` (`AssemblyNewPartBody`, same fields as a purchase line + acquisition cost).
  - Remove `POST /parts/{unitId}/remove`: back to stock, or to another build (`targetAssemblyId` + `targetRowVersion`).
  - Replace `POST /parts/{unitId}/replace` (`replacementUnitId`): from free stock, or a part of another build (`otherRowVersion`). Remove/replace return `AssemblyView[]` — take the one with this id.
  - Revenue split `PUT /allocations` (`AssemblyAllocationRequest`): percent per part, pure rule "sum = 100" with the difference shown; "reset to default" sends the per-part standalone ratio computed in a pure helper.
  - Publish / unpublish / disassemble (`POST …/publish|unpublish|disassemble`, `RetailVersionRequest`; disassemble confirms). Photos upload/delete. "Preview in store" → `/builds/<code>` when Published.
- Leave out (no API): drag to reorder parts, "sell the build" shortcut (POS covers it).

### c2 — Partners `/admin/partners` (ADM-Partners)
- List `GET /retail/partners` → KPIs computed on the page: total capital, total due, total recoverable, unsold financed units. Table: name, basis (FinancedParts "على القطع اللي مولها" / WholeShop "ربح المحل كله"), default %, capital, financed units, due, active. "شريك جديد" (`Finance.ManagePartnerAgreements`).
- Detail below (`?partner=<id>`): `GET /retail/partners/{id}` → info + edit form (`PartnerRequest`: name, phone, join date, default %, basis, loss sharing, active, notes; `rowVersion`), financed parts table (code, name, status, cost, percent with "changed" in orange when `percentOverridden`, link to `/admin/inventory?search=<code>` to change it there — `FinancedPartView` has no unit row version).
- Capital `GET/POST /partners/{id}/capital` (`PartnerCapitalRequest`: Deposit/Withdrawal, amount, date, method, money account from `GET /retail/money/accounts` when `Finance.ViewVaults`, note). Append-only: no edit/delete.
- Payouts `GET/POST /partners/{id}/payouts` (`Finance.PostPartnerSettlements`; amount, method, account, reference, note). Show `offsetApplied`.
- Statement `GET /partners/{id}/statement?from&to` → opening/closing capital, earned, paid, recovered, lines; a print-styled view with "PDF" = `window.print()` (like the builder quote page).
- Month close `POST /partners/month-close` `{ year, month }` (`Finance.ManagePartnerAgreements`, confirm) → show store net, financed shares, base and posted earnings. Default = previous month (Cairo).
- Leave out (no API): partner stock value and "profit this month" KPIs.

## 3. Rules
- Kit only: `DataTable`, `FilterBar`, `Pager`, `useUrlFilters`, `useSubmit`, `ConfirmDialog`, `Dialog`, `Toast`, `PageHeader`/`FormMessage`. Missing kit piece → stop and report, no second version.
- One `<area>-api.ts` per feature (`browserApi()` + `unwrap` + `required`), one `<area>-rules.ts` for pure logic with `node:test` tests next to it (`*.test.ts`, `.ts` imports). Reuse `fetchPartners` and `fetchCategories` — do not copy them; if two features need the same new call, put it in one place and import it.
- Forms reload only on 409 (`isConflict`), so server field errors stay visible.
- Hide what the permissions do not allow (`usePermissions().has`). Cost/profit only when the API returned them (non-null).
- Strings in `apps/web/messages/ar.json` and `en.json` under `admin.inventory`, `admin.purchases`, `admin.builds`, `admin.partners`. Egyptian Arabic, short. Condition only "جديد"/"مستعمل" (`ConditionBadge`). Status/kind/method labels through one pure mapper per area, unknown → generic label. Use ICU plurals for counts.
- RTL first, English works, dark mode via tokens, 375px phone (tables scroll in their box, forms stack, two columns only from `xl`). Arabic/English content fields take their own `dir`.
- Pages: server `page.tsx` with metadata + `hasLocale`, renders the client screen (like `app/[locale]/admin/orders/page.tsx`).
- Do not touch: backend, API contract, kit, shell, nav, auth. No new npm packages, no TODOs, no dead code, files under ~300 lines.
