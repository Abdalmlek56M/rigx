## 2. Goal
Today the preview seed creates only an owner and catalog products, so the storefront and the admin are empty (the store sells **stock items** `RX-…` and **builds** `BLD-…`, not catalog products).
Extend the Development preview initializer so one call to `POST /api/v1/development/preview/initialize` gives a realistic demo store:

| Data | Amount | Notes |
|---|---|---|
| Stock items (RX) | ~30, published, with price and the existing generated images | mix of New and Used; CPUs, GPUs, boards, RAM, SSD, PSU, cases, coolers; 4 of them sold out (quantity 0) |
| Builds (BLD) | 3 published | made from the stock items above (gaming, study/work, budget) |
| Customers | 10 | Egyptian names, fake phones `01000000001…`, emails `demo1@example.com…`, 1–2 saved addresses each |
| Online orders | ~12 | spread over every customer status: New, Confirmed, Preparing, Shipped, Delivered, Cancelled; Delivery and Pickup; COD/InstaPay/Wallet |
| POS sales | ~5 | confirmed, paid |
| Expenses | ~6 | rent, electricity, shipping supplies |
| Content | FAQs (6) + the 5 policies (Shipping, Returns, Exchanges, Warranty, Terms) published, short Egyptian Arabic text | |
| Settings | shipping governorates with fees (Cairo, Giza, Alexandria + 3 more), pickup enabled with a demo address | only if they are empty |

Dates: spread orders over the last 30 days (Cairo business day). Prices in EGP, realistic for Egypt.

## 3. Rules (must)
- **Development only.** Keep the existing guards (`Preview:Enabled` + Development environment + bootstrap key). Never runs in Production.
- **Through the real services, not raw SQL/EF inserts**, so domain rules, stock, invoices, warranty and audit behave like real use. Resolve the module services from DI (`IServiceScopeFactory`) as `RetailTestServices` does with its constructors. If a service needs an acting user, use the preview owner.
- **Idempotent.** A second call must not duplicate anything: skip the demo block if it already exists (e.g. check for a known demo customer email or a demo item model) and report counts as 0 for skipped parts.
- **Fake data only.** No real people, phones, emails, addresses or secrets. Emails `@example.com` only.
- Customer-facing text: only "جديد"/"مستعمل" for condition; Egyptian Arabic, short.
- Do **not** change: Domain rules of any module, migrations, the API contract (`packages/api-client/openapi.v1.json`), `apps/web`, auth/permissions. If a seed needs something that does not exist, **stop and write it in your report** — do not invent a new endpoint or rule.
- No new NuGet/npm packages. No dead code, no TODOs. Keep files under ~300 lines: put the demo data in a new file next to the service (e.g. `PreviewDemoData.cs`) instead of growing `PreviewInitializationService.cs`.
- Extend `PreviewInitializationResult` with the new counts (stock items, builds, customers, orders, expenses).
