# مجمّع الحواسيب وقوالب التجميعات وقواعد التوافق (PC Builder & Build Templates)

تاريخ التحديث: نوفمبر 2026  
الحالة: **مسودة للمراجعة والاعتماد (Pre-Foundation Final Draft)**  

---

## 1. نطاق مجمّع الحواسيب في الإصدار الأول (V1 Scope)

لتفادي التعقيد غير المبرر وأخطاء إدخال البيانات المادية الضخمة، تم ضبط نطاق الفحص التوافقي ليركز على **التوافق الكهربائي والمعماري الحتمي**، مع استبعاد القيود الفيزيائية كأبعاد الصناديق والمبردات:

```
[الفحوصات المعتمدة في V1]
  ├── 1. تطابق المقبس (CPU Socket == Motherboard Socket)
  ├── 2. دعم المعالج والـ BIOS (CPU Support on Motherboard & BIOS version when data exists)
  ├── 3. جيل الذاكرة العشوائية (RAM Generation: DDR4 vs DDR5)
  └── 4. تقدير استهلاك الطاقة التقديري (Advisory Wattage Estimation)

[الفحوصات المستبعدة صراحةً من V1]
  ├── X أبعاد وطول كارت الشاشة داخل الصندوق (GPU Physical Length)
  ├── X أقصى ارتفاع للمبرد الهوائي داخل الصندوق (Max Cooler Height)
  └── X مقاسات ومواضع وسمك تركيب الردياتير المائي (Radiator Fitment)
```

## 2. قواعد التوافق الأساسية المعتمدة (Core Compatibility Rules)

### 2.1 توافق المعالج واللوحة الأم (CPU <-> Motherboard)
* **القاعدة:** مقبس المعالج يجب أن يطابق مقبس اللوحة الأم تماماً:
  $$\text{CPU.Socket} == \text{Motherboard.Socket}$$
* **دعم إصدار الـ BIOS:**
  - عند توفر بيانات متوافقة، يوضح النظام ما إذا كانت الشريحة تدعم المعالج مباشرة (Out of the box) أم قد تتطلب تحديث الـ BIOS، مع إمكانية توفير خدمة التحديث مجاناً بالمتجر.

### 2.2 توافق الذاكرة العشوائية (RAM Compatibility)
* **القاعدة:** جيل الذاكرة يجب أن يطابق جيل منافذ اللوحة الأم:
  $$\text{RAM.Generation} == \text{Motherboard.SupportedMemoryType} \quad (\text{DDR4 with DDR4, DDR5 with DDR5})$$
* **عدد المنافذ:** لا يتجاوز عدد قطع الرام المختارة إجمالي عدد منافذ الذاكرة في اللوحة الأم.

### 2.3 تقدير استهلاك الطاقة الاسترشادي (Advisory Power Estimation)
* **المعادلة الاسترشادية:**
  $$\text{Estimated Wattage} = \text{CPU.TDP} + \text{GPU.TDP} + \text{System Overhead (\approx 50W - 80W)}$$
* **تنبيه هام:**
  - حساب استهلاك الطاقة هو **مؤشر إرشادي فقط لمساعدة العميل**، ولا يمثل ضماناً هندسياً أو كهربائياً مطلقاً لسلامة النظام.
  - يُعرض للمستخدم النطاق الموصى به لمزود الطاقة (مثلاً: *"الموصى به لمكوناتك: 650W أو أعلى"*).

### 2.4 معالجة نقص المواصفات (Incomplete Specs Handling)
* إذا كانت بيانات أحد المكونات ناقصة أو غير مدخلة بالكامل في قاعدة البيانات، **لا يفترض النظام التوافق**، بل يظهر تنبيه واضح بلون كهرماني:
  > **"التوافق غير مؤكد: نظراً لعدم اكتمال المواصفات الفنية للقطعة المختارة، يُرجى مراجعة الدعم الفني بالمتجر للتأكيد."**

## 3. نظام قوالب التجميعات والبدائل (Configurable Build Templates)

ميزة محورية تتيح للمتجر عرض أجهزة متناسقة وجاهزة مع منح العميل حرية التخصيص:

```
[قالب تجميعة معتمد: Mid-Range Gaming Rig]
  ├── خانة المعالج (Slot 1: CPU - إلزامية)
  │     ├── خيار افتراضي: Intel Core i5-14400F
  │     ├── بديل 1: Intel Core i5-14600K (+ فارق السعر)
  │     └── بديل 2: Intel Core i7-14700F (+ فارق السعر)
  ├── خانة كارت الشاشة (Slot 2: GPU - إلزامية)
  │     ├── خيار افتراضي: RTX 4060 8GB
  │     └── بديل 1: RTX 4060 Ti 16GB
  ├── خانة الرام (Slot 3: RAM - إلزامية)
  └── خانة التبريد المائي (Slot 4: Optional Cooler - اختيارية)
```

### قدرات إدارة القوالب:
1. **تحديد الخانات الإلزامية والاختيارية:** يحدد مسؤول المتجر الخانات الأساسية (معالج، لوحة، رام، مزود) والخانات التكميلية (مبرد، كابلات احترافية، إضاءة).
2. **إضافة بدائل متعددة لكل خانة:** كل بديل يرتبط بمنتج حقيقي (`product_id`) ورصيد فعلي في المخزن.
3. **إعادة الحساب اللحظي:** عند اختيار العميل لبديل أعلى أو أدنى:
   - يُعاد حساب السعر الإجمالي للسلة فوراً.
   - يُعاد فحص توفر المخزون الحقيقي للبديل المختار.
   - يُعاد حساب تكلفة التجميعة وهوامش الربح للمتجر.

## 4. التجميعات المخزنية والقطع الجديدة والمستعملة (Assemblies & NEW / USED)

1. **حالة القطع (Condition):**
   - كل قطعة ومكون في المتجر يحمل تصنيفاً صريحاً: جديد (`NEW`) أو مستعمل (`USED`) أو مفتوح الصندوق (`OPEN_BOX`).
   - يُمنع خلط القطع المستعملة في تجميعة معلن عنها أنها جديدة بالكامل دون توضيح ذلك للعميل في الفاتورة والضمان وسجل الصنف.
2. **سلامة حركة المكونات مخزنياً:**
   - عند بيع تجميعة جاهزة تم تجميعها مسبقاً في المعرض، تُسحب القطع المكونة لها من المخزن بحركاتها وسيريالاتها الرسمية لضمان عدم وجود أرصدة وهمية أو سيريالات مفقودة.

## 5. قواعد التبديل والتعديل التزامني لمكونات التجميعة (Atomic Component Swapping)

أثناء تجهيز التجميعة أو فحصها في ورشة العمل أو بناءً على طلب العميل، قد يتطلب الأمر استبدال قطعة بأخرى:

1. **المعاملة الذرية الواحدة (Single Atomic DB Transaction):**
   - تحرير وإعادة القطعة المستبدلة القديمة (Old Component) إلى رصيد المخزن المتاح بحالتها وسيريالها وتكلفتها الأصلية كاملة دون أي فقدان.
   - حجز أو سحب القطعة البديلة الجديدة (New Component) بحالتها وسيريالها وتكلفتها المحددة.
   - تتم العمليتان داخل معاملة قاعدة بيانات ذرية واحدة تضمن إما إتمام التبديل بالكامل أو التراجع عنه في حال حدوث أي خطأ، مما يمنع منعاً باتاً ظاهرة حجز القطعة مرتين (Double-booking) أو تشتت السيريالات.
2. **إعادة الاحتساب المالي الفوري:**
   - إعادة احتساب إجمالي سعر التجميعة تلقائياً مع حساب فروق الأسعار (Price Difference).
   - إعادة احتساب تكلفة البضاعة المباعة (COGS) وهامش ربح الجهاز فور اكتمال التبديل.
3. **سجل التدقيق والتتبع الإلزامي (Mandatory Audit Trail):**
   - تسجيل كل عملية تبديل في سجل أحداث غير قابل للحذف يتضمن:
     - معرف الموظف المنفذ للتبديل (`OperatorPersonId`).
     - الختم الزمني الدقيق بالثانية (`Timestamp`).
     - سبب التبديل الإلزامي (`SwapReason`) مثل: عيب فني أثناء الاختبار والتشغيل، ترقية بطلب العميل، عدم توفر السيريال الأصلي.
     - السيريالات القديمة والجديدة التي تم تبديلها.
