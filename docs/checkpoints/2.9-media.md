# Checkpoint: 2.9 Media

Date: 14 Nov 2026

## Done
- Watermark on upload for stock item and build photos (and article images only when `ApplyToArticles`), from settings: position, opacity, size (% of image width), margin 3% of the shorter side. Applied to the full image and the thumbnail; the `.original` file is always kept clean. Logo = watermark logo, else store logo; no logo or disabled = no watermark. Code: Catalog `CatalogMediaStorage` (`ImageWatermark`), `WatermarkPlacement`.
- Logos: `logos` jsonb on store settings (not a settings section, so the section PUT never touches them). `PUT/DELETE /api/v1/admin/storefront/settings/logos/{store|watermark}` (`System.StoreSettings`, audited `Storefront.LogoUpdated` / `Storefront.LogoRemoved`), new key every upload. Public settings view shows the store logo key only. Domain `Storefront/Domain/Settings/StoreLogos`, `SaveSettingsLogoAsync`.
- Re-apply: `POST /api/v1/admin/storefront/settings/watermark/reapply` (`System.StoreSettings`) returns 202. Background `WatermarkReapplyJob` (single worker, channel, signals merged) runs `WatermarkReapplyService`: re-renders every stock item and build photo from its original with the current settings into new keys (public media is cached immutable), then swaps them with a conditional update. Old files stay (orders keep old thumbnails) until orphan cleanup. Turning the watermark off and re-applying removes it. Host `Media/WatermarkReapply`, `Media/MediaWatermarkSource`.
- Private images under `private/{requests|receipts}/...`, re-encoded WebP (EXIF stripped), `SavePrivateImageAsync`. Public `GET /api/v1/catalog/media/...` 404s `private/`. Orphan cleanup skips `private/` and `settings/`. Host `Media/PrivateMediaResults`.
- Request photos: `POST /api/v1/requests` returns `photoUploadToken` for Sell, TradeIn, Upgrade, Support (32 random bytes, only the SHA-256 hash stored, 30 min; a duplicate submission issues a fresh token). Public `POST /api/v1/requests/photos` (form `token` + `image`), rate limit `request-photo` 20 / 10 min per IP; bad or expired token 404, max 5 photos 409; never watermarked. Admin `GET /api/v1/admin/requests/{id}/photos/{index}` (`Requests.View`, `no-store`); detail view has `photoCount`. Rules in Storefront `Domain/Requests/RequestPhotoRules`, service `Features/Requests/RequestPhotoService`.
- Expense receipt image: `PUT /api/v1/admin/retail/expenses/{id}/receipt` (`Finance.ManageExpenses`), `GET` same route (`Finance.ViewReports`, `no-store`, 404 when none). Free-text `AttachmentReference` removed from the create request. Column renamed `receipt_storage_key` (old free-text values cleared); view has `hasReceipt`.
- Migrations: Storefront M40 `M40_MediaLogosRequestPhotos`, Retail M41 `M41_ExpenseReceipt`.
- Tests: `MediaRulesTests` (18, no DB), `MediaTests` (8, real PostgreSQL).
- Full suite 866/866 (14 Nov 2026)
