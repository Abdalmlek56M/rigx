# Checkpoint: 2.3 Assemblies

Date: 13 Nov 2026 · Branch `feat/2.3-assemblies` (merged to `main`)

## Done
- Build card: usage (`Gaming` / `Editing` / `StudyWork` / `Streaming`), sell mode (`Full` / `FullOrSplit`), build warranty from the settings list (empty = per part), copies count, "مناسبة لـ" (ar/en), photos (max 12, same media storage + media-delete guard as stock items). `PUT /api/v1/admin/retail/assemblies/{id}`, `GET …/assemblies/{id}`, `POST/DELETE …/assemblies/{id}/photos`.
- Parts: price inside the build (`PartPrice`, default = item in-build price), warranty override (wins over the build's), partner % override on the unit. `PUT …/assemblies/{id}/parts/{unitId}`.
- Add from stock `POST …/parts`; add a part that is not in stock `POST …/parts/new` (creates a one-piece RX item straight into the build; warranty from settings, specs checked against the category schema).
- Remove `POST …/parts/{unitId}/remove`: back to stock, or into another build (`targetAssemblyId`). Replace `POST …/parts/{unitId}/replace`: from an available unit, or swap places with another build's part. Old `DELETE …/units/{unitId}` and `POST …/assemblies/swap` removed.
- Revenue split: adding resets to defaults (alone prices), removing rebalances, a replacement takes the old share. Fixed: moving a part into another build used to leave that build's split above 100%.
- Storefront `GET /api/v1/store/assemblies?usage=&minPrice=&maxPrice=` with usage, sell mode, copies, warranty, "suitable for", photos, per-part warranty; part prices only when the build can be split. Costs/partner fields hidden without `Inventory.ViewCosts` on every admin build response.
- Rules in `Retail/Domain/AssemblyRules.cs`; features split into `AssemblyService` (card, publish, photos, list) and `AssemblyPartService`; intake item creation shared via `StockItemFactory`.
