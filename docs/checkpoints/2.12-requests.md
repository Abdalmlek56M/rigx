# Checkpoint: 2.12 Requests inbox

Date: 13 Nov 2026

## Done
- One requests inbox (`customer_requests`, Storefront, migration M30) replaces contact messages: `contact_messages` copied into it as type Contact, then dropped. `/api/v1/contact` and `/api/v1/admin/contact-messages` removed.
- Types: Sell, TradeIn, Upgrade, NotifyMe, Support, Contact, Service. Service kinds: Consult, Build, Test, Maintenance, Sourcing, Upgrade; optional preferred date, not in the past.
- Public code `REQ-xxxx` (PublicCode prefix REQ, own sequence).
- Public submit: anonymous (links the user if signed in). Egyptian mobile required, normalized by the shared `Common.Domain.EgyptMobile` (also used by Purchasing); email, governorate and source optional. Per-type required fields: Sell/TradeIn need model; Upgrade/Support/Contact need message; NotifyMe needs item code or model; Service needs kind. Honeypot; duplicate within 10 min returns the same code; rate limit `customer-request` 5 / 10 min per IP.
- Statuses: New, Following, Offered, Accepted, Rejected, Converted, Closed. Rules in `Domain/Requests/CustomerRequestRules`:
  - Following: from New, or reopen a Closed.
  - Closed: from anything except Converted.
  - Offer (amount + optional internal expected resale) only for Sell/TradeIn/Upgrade, moves to Offered; revisable from Following/Offered/Rejected.
  - Decision Accepted/Rejected only from Offered.
  - Convert only Accepted Sell/TradeIn.
- Conversion (Host `RequestPurchaseConversion`): finds the seller by phone or creates a Person seller; creates a Draft purchase PO-xxxx with one Used line (cost = offer, price = expected resale or offer, payment Cash 0 to edit later); marks the request Converted with PurchaseId/PurchaseCode (conditional update; the draft is cancelled if that fails).
- Admin: list with filters, get, WhatsApp link, status, offer, decision, internal note. Row version on every write (409).
- Permissions `Requests.View`, `Requests.Manage` (new, M31); granted to roles that had System.StoreSettings or Purchasing.CreateOrder.
- Tests: unit `CustomerRequestRulesTests` (rules, EgyptMobile, WhatsAppReply, REQ code); integration `RequestsTests` (submit, honeypot, duplicate, permissions, list filters, offer→decision→convert, seller reuse, 409s, WhatsApp link); `CustomerRequestMigrationTests` (M30 data copy). Full suite 627/627.
