# Checkpoint: 2.6 Invoicing

Date: 13 Nov 2026

## Done
- Invoice issued on Delivered, in the same transaction as the warranties (invoice date = warranty start). One invoice per order (idempotent).
- Number `{prefix}-{YYYY}-{NNNN}`, prefix from invoice settings (default INV); gap-free per year from counter table `invoice_counters`; year = Africa/Cairo year of issue (changed 13 Nov 2026). Table `invoices`.
- Seller name = staff member who marked the order delivered (snapshot).
- Kind computed: Build (تجميعة كاملة) if any build line, else Parts (قطع منفردة). Status computed: Void when the order is cancelled, else Issued.
- Content read live from the order: lines, parts with RX code, condition, serial, warranty label / end / status; lines total, discount, shipping, total, paid, remaining, refunded.
- Public link `GET /api/v1/invoices/{token}` (`/i/{token}` on the frontend, unguessable 32-byte token): anonymous, rate-limited (order-tracking policy), no-store. Returns invoice + branding from settings (store name, background-logo watermark flag, warranty QR flag, terms line, contacts marked "show on invoice", pickup address) + invoice URL + warranty lookup URL (only when the QR flag is on).
- Customer list `GET /api/v1/invoices/mine`.
- Email on delivery (outbox, stage `Invoiced`, Egyptian Arabic, link to the invoice) when the order has an email. A repeated status request sends no email again (also fixes duplicate confirmed/shipped emails).
- Admin: `GET /api/v1/admin/retail/orders/{id}/invoice`, `GET /api/v1/admin/retail/invoices?q=&page=` (`Sales.ViewOrders`; q = invoice number, RIGX order reference or phone; 50 per page). Phone masked and address hidden without `Sales.ViewCustomerContact`; serial hidden without `Inventory.ViewSerials`.
- Quote `POST /api/v1/store/quote`: anonymous, rate-limited, no invoice number, no customer data. Lines = stock items / published builds priced like checkout; a single build gets its title, usage and parts with condition and part price; total; priced-at time; same branding.
- Warranty lookup accepts the invoice number (parsed first; `RIGX-` order reference still works). Lookup groups, account and admin warranty rows carry `InvoiceNumber`.
- Fix: warranty BuildCode for a split build sale is now the BLD code (was the part's RX code).
- Dead permissions `Invoices.ManageTemplates/ReviewDraft/IssueFinal/Reprint` removed (migration M28).
- Migrations: M27 (Retail: `invoices`, `invoice_counters`), M28 (Identity: remove invoice permissions).
- Code: rules `Retail/Domain/InvoiceRules.cs`; entities `Retail/Domain/InvoiceEntities.cs`; features `Retail/Features/Invoicing/` (`InvoiceRegistry`, `InvoiceService`, `QuoteService`); Host `Retail/RetailEndpoints.Invoicing.cs`, `Retail/InvoiceDocuments.cs` (branding wrapper). Invoicing lives inside Retail (shares the order schema).
- Tests: unit `InvoiceRulesTests`, integration `InvoicePostgreSqlTests` (16), authorization matrix updated.
- Tests: full suite 511/511.
