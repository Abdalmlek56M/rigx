### K. Coupons — done 20 Nov 2026
- **What it is:** one code per influencer or ad. Each code has a source name, so the owner sees which source brings sales. Admin → المبيعات → الكوبونات (`/admin/coupons`, permission `System.StoreSettings`, like offers).
- **A code has:** the code (A–Z, digits, dashes, 3–30, stored upper case, typed in any case), the source, a percent (up to 90%, optional cap in EGP) or an amount, an optional minimum order, an optional total number of uses, "once per customer" (by phone, on by default), optional start and end, on/off.
- **Owner-level decisions (delegated, defaults picked):**
  - The discount is on the items only, never on shipping. The store's minimum order is checked before the coupon.
  - One coupon per order. In POS it comes after the cashier's discount and does not count toward the cashier's discount limit.
  - A cancelled order gives its use back. Uses, revenue and discount in the report count every order that is not cancelled; completed orders are shown apart.
  - Revenue = the order's items after discounts, without shipping. Revenue and discount given show only to people with the reports permission.
  - A used code cannot be renamed or deleted (so the report keeps matching what was shared); it is turned off instead.
  - Coupons survive the "business" data reset (like partners and expense types); their numbers start from zero with the orders.
- **Where:** rules in `Retail/Domain/CouponRules.cs` (code format, input checks, when a code works, the discount). `Features/Coupons/` (`CouponService` admin + report + check, `CouponRedemption` shared by checkout and POS: locks the coupon row so two orders cannot take its last use, then spreads the discount over the lines like the order discount). Orders keep `coupon_id`, `coupon_code`, `coupon_discount` (migration M53 Retail, additive).
- **API:** `GET/POST /api/v1/admin/retail/coupons`, `PUT/DELETE …/{id}`; public `POST /api/v1/store/coupons/check` (rate limit 20 per 10 min per IP); `CheckoutRequest.couponCode`, `PosSaleRequest.couponCode`, `PosPreview.coupon`; `OrderView` / `CustomerOrderView` carry `couponCode` and `couponDiscount`. A refused code at order time is a 400 on `couponCode` whose message is the problem code (`NotFound`, `Inactive`, `NotStarted`, `Expired`, `BelowMinimum`, `UsedUp`, `AlreadyUsed`); the web words it.
- **Web:** admin list = the report (source, discount, status, uses / limit and completed, revenue, discount given, last use, totals line), form, edit, turn off, delete while unused. Checkout: "كود الخصم" box in the order summary with "تطبيق", the applied code, a "خصم الكوبون" line. POS: a code field in the summary with the discount or the reason it does not work. Order success, account order and admin order show "خصم الكوبون (CODE)". Activity log: Arabic names for the coupon table and fields.
