# Plan: Phase 4.10 part b — owner feedback round 2 (19 Nov 2026)

The owner reviewed the live site after 4.10a and sent a long list (storefront, admin, data, content).
This file splits it into workstreams. Each one runs in its own session, on its own branch, and lands on `main` with tests green.
Every workstream uses the installed design skills (`docs/10-ai-tooling.md`): impeccable, design-taste-frontend, emil-design-eng, web-design-guidelines, userinterface-wiki, mobile-native.
Each one is checked in the browser on desktop and phone, in light and dark.

### Back-in-stock alert — done 19 Nov 2026
- **Already in place (2.8):** the 10-minute `BackInStockJob` matches waiting notify-me requests and sends one email when the customer gave an email. The admin "رجعت للمخزون" list in `/admin/requests` shows a `wa.me` link (opens in a new tab) with the `BackInStock` WhatsApp template ({الاسم} {القطعة} {اللينك} = product link). "اتعلم إنه اتبعت" closes the request. Each request is alerted once.
- **Added:**
  - **Condition:** the notify-me sheet asks "أي حالة / جديد / مستعمل". `CustomerRequest.Condition` (migration M52) stores the choice, null = any. `NotifyMeRules.CheckCondition` / `Pick` hold the rules. A match needs the same model and the chosen condition; "any" takes the cheapest item. "Available now" (409) also respects the condition. Retail `FindAvailableAsync` now returns the cheapest item per condition.
  - **No wait:** opening the back-in-stock list runs the same matcher first (each request matches at most once), so stock received minutes ago shows without waiting for the job.
  - **Admin:** each row shows the customer's phone and the condition they asked for, and the request detail shows the wanted condition.
- **Decision (owner delegates):** delivery stays staff-assisted (wa.me + email). The **WhatsApp Cloud API** (Meta, approved templates, a paid-per-message business number) can send automatically later, from the same matcher; it is left for Phase 5 with campaigns.
