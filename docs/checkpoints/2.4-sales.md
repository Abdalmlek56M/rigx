# Checkpoint: 2.4 Sales / POS / orders

Date: 13 Nov 2026

## Done
- Website checkout `POST /api/v1/orders`: guest allowed when "guest checkout" (`Controls.GuestCheckoutEnabled`, default off) is on, otherwise sign-in needed. Structured address (governorate code, area, street, building/floor/flat, landmark), "same number on WhatsApp", optional email, optional usage ("هتستخدمه في إيه؟": Gaming / Editing / StudyWork / Streaming / Upgrade / Other + text) and lead source ("عرفتنا منين؟", from the settings list). Lines are stock items (Alone or WithBoard price) or published builds, re-priced in Retail; catalog-product order lines removed. Delivery fee by governorate group, upfront (shipping + deposit), enabled payment methods (cash on delivery / InstaPay / wallet) and minimum order from store settings. Rate-limited.
- Statuses: New → Confirmed → Preparing → Shipped → Delivered → Completed (+ Cancelled). "Ready" replaced by "Shipped"; pickup goes Preparing → Delivered.
- Reservation: stock claimed on Confirmed and held for the settings default (24 hours, owner decision 13 Nov 2026). Per order the admin can restart the hold and choose the end action: notify only (default; order flagged `ReservationExpiredAtUtc`) or release (order cancelled, stock back). Background job checks every minute.
- Shipping details: courier (defaults to the courier in shipping settings) + waybill number.
- Public tracking `GET /api/v1/track/{token}` and page `/t/{token}`: timeline, courier, waybill, area/street, items, remaining to pay; no name/phone/email; Completed shows as delivered. Satisfaction score 1–5 once after delivery: `POST /api/v1/track/{token}/rating`.
- Blacklist `/api/v1/admin/retail/blacklist`: by phone, email or address (or copied from an order). Matching orders are flagged and confirmed only after full prepayment.
- Payments `POST /api/v1/admin/retail/orders/{id}/payments`: cash / InstaPay / wallet / bank transfer. Order becomes Paid when payments cover the total; paid and remaining shown on the order.
- POS: `POST …/pos/preview`, `POST …/pos/sales`, `GET …/pos/customers?phone=`. Free sale price per line (below shown price = discount), order-level discount, discount limit = settings % (default 10%) unless the seller has `Sales.OverrideMinimumPrice` (owner decision 13 Nov 2026), below-cost warning in preview, split payment (method `Split`), confirm now (stock claimed) or save as pending, pickup or shipping with a typed fee, split build sale (FullOrSplit builds: chosen parts sold at their prices, the rest back to stock, build closes as Disassembled), customer search by phone. Old manual route `POST /api/v1/admin/retail/orders` removed.
- Build copies (owner decision 13 Nov 2026): when one copy of a build with Copies > 1 is sold, the sold parts leave the build and each is replaced by an available unit of the same RX item (same part price, warranty, share); copies − 1. A part with no replacement leaves the build in Draft for the owner to complete. Cancelling that order returns the sold parts to stock.
- Order emails via the email outbox (Arabic): received, confirmed, shipped, each with the tracking link (`Sales:TrackingBaseUrl`, default `http://localhost:3000/t/`).
- Public "اتباع قبل كده" feed `GET /api/v1/store/sold?kind=&categoryId=&page=`: delivered items/builds, no prices or customer names, governorate only when the setting is on.
- Store settings section "sales": ReservationHours 24, ReservationAutoRelease false, PosMaxDiscountPercent 10, SoldFeedEnabled true, SoldFeedShowGovernorate false.
- Code: rules in `Retail/Domain/OrderRules.cs`; features in `Retail/Features/Sales`: `OrderService` (checkout, reads), `OrderDrafting` (pricing shared by checkout and POS), `OrderStatusService`, `OrderStockAllocator` (claim/release, split, copies refill), `OrderPaymentService`, `OrderFulfillmentService` (shipping, reservation, expiry), `OrderTrackingService`, `BlacklistService`, `PosService`, `SoldFeedService`. Host: `Retail/RetailEndpoints.Sales.cs`, `Retail/OrderEmails.cs`, `Retail/ReservationExpiryJob.cs`.
- Migrations: M24 (Retail: order columns, `order_payments`, `blacklist_entries`, data moved) and M25 (Storefront: sales settings column).
- Tests: full suite 427/427 (SalesTests 29 integration tests, OrderRulesTests unit tests).
