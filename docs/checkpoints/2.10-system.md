## Done (part B — backups + reset)
- Backup: `rigx-backup-{yyyyMMdd-HHmmss}Z.zip` = `database.dump` (pg_dump custom format, password via env), `media/` (incl. `private/` and settings logos), `manifest.json` (time, version, SHA-256 of dump, applied migrations per context). Built in a temp folder, then copied atomically to every destination in `System:Backup:Destinations` (two folders, paths only from config). No destination → 409. A run succeeds only if every destination got the file.
- Schedule: store settings section `backup` (Enabled true, HourCairo 3, RetentionDays 14; limits hour 0–23, retention 3–90). Hourly `BackupJob` runs once per Cairo day after the hour and retries a failed day. Retention deletes old archives by file-name timestamp.
- `backup_runs` (Auditing): trigger Scheduled / Manual / BeforeReset, status, file, size, SHA-256, destinations written, error, verify result.
- Endpoints `/api/v1/admin/system/backups`: `GET` list; `POST` run now (`System.ManageBackups`); `POST /{id}/verify` restore drill into a temp database `rigx_restore_check_*` (always dropped; SHA check; table and row counts); `GET /{id}/download` owner-only (`System.BackupDownload`) + step-up, `no-store`. Audit `System.BackupCreated/BackupVerified/BackupDownloaded`. Real restore is manual (see `06-operations.md`).
- Dump and drill connection: `ConnectionStrings:Backup` → `Migrations` → `Default` (the app role cannot create databases). Docker runtime image installs `postgresql-client-17` (PGDG); image build not yet tested.
- Data reset: `POST /api/v1/admin/system/reset` `{sections, confirm: "RESET"}`, owner-only (`System.ResetData`) + step-up. A successful BeforeReset backup runs first, else 409 and nothing is deleted. Sections: `business` (stock, builds, purchases, sellers, orders, invoices + counters, warranties, money movements with accounts kept, expenses, partner ledger with partners kept, requests, saved builds, wishlists, private photos), `content` (articles, FAQ, media assets + files), `customers` (customer-only accounts + sessions, addresses, Google links; needs `business`).
- Never reset: staff, roles, settings, logos, categories/brands/specs, products, audit logs, backup runs, RX/BLD/PO/REQ sequences, blacklist, offers, policies, reviews.
- Reset mechanics: per-module transaction (`TableReset`, explicit table lists, FK-ordered DELETE); no cross-module rollback, so the backup is the recovery. Audit `System.DataReset` (also on failure). Security audit FKs to user accounts are now ON DELETE SET NULL, so audit rows survive a customer reset.
- Migrations: `M46_BackupRuns` (Auditing), `M46_BackupSettings` (Storefront), `M46_BackupPermissions` (Identity; owner gets ManageBackups, BackupDownload, ResetData).
- Tests: `BackupRulesTests` (6), `BackupTests` (8, real pg_dump/pg_restore in the Testcontainers container), `DataResetTests` (5). Full suite 910/910.
