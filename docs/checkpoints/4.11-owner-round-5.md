### 2.2 Background effects (dark theme)
The owner asked what we think. **Recommendation: two layers, dark theme only.**
1. *Ambient glow* (CSS only, free): two soft orange/blue radial lights drifting slowly behind the hero and the rails.
2. *Circuit traces* (one `<canvas>`, hero + page header only, not the whole site): thin PCB lines, a faint light pulse travels along some of them, a little brighter near the pointer. 60 fps cap, paused when the tab is hidden or the canvas is off-screen, off for `prefers-reduced-motion`, `save-data`, and low-end devices (`hardwareConcurrency <= 4` → static version), static image fallback.
Skipped: connected-particles network (cliché, heavy), hex rain (noisy, hurts reading), spotlight grid (nice but a second effect competes with the traces), airflow waves (fine later as a section accent). Light theme keeps the calm workshop look.

## 3. Decisions
Answered now (owner delegates, recorded):

Added rule (default): the phone number is masked and, 90 days after delivery, the page shows only the status. The owner can say "never expire".
- **Model choice:** plan, domain and final review stay with Opus; clear feature code and tests with Sonnet; this matches `CLAUDE.md`. For this round Opus medium is enough for phases A, E, F; use Opus high only for C (visual identity) and D (builder) where taste decides.
- **DeepSeek follows the architecture:** `AGENTS.md` already tells it to read `CLAUDE.md`, the standards and its brief first. Each brief repeats the exact files and the rules of §5 so it cannot choose its own way. Round-5 work is done by Claude sessions; DeepSeek only gets the repetitive briefs (copy pass, icon swaps) afterwards.
- Checkout: payment section moves before the optional ones (default; the owner had delegated).
- Categories "تخزين", "كيسات", cooling in two: these are data. The owner renames them now in the admin (`/admin/categories`); the base seed uses the new names for new stores in phase F.

Needs the owner (default if he does not answer):

## 5. Rules for every phase
1. **The bar (owner's words):** comfortable, beautiful, professional; sections in cards with a title; little noise; one clear action per area; icons instead of words where an icon is clear (tooltip + `aria-label`); formal Arabic; strong but not excessive motion; every effect honours reduced motion; light and dark both work.
2. **Code:** rules in Domain, small single-purpose components, no duplicated helpers, no dead code, tests for every rule (`docs/04-engineering-standards.md`). No new dependency without the owner's yes (only `@dnd-kit/core` is proposed).
3. **Tools:** `impeccable`, `design-taste-frontend` (calm: no shader scenes outside the dark hero canvas), `emil-design-eng`, `web-design-guidelines`, `userinterface-wiki`, `mobile-native`, `break-ui`, `performance`. Use them as reviewers; the decision stays in this file.
4. **Verification:** typecheck, lint, tests, production build, and a browser pass at 375/768/1024/1440 in ar and en on a **production build** (dev mode hides the ISR/hydration defects of D1/D2).
5. **Routing** per `CLAUDE.md`; the checkpoint (this file) is updated at each commit.
